# 첫 고객 한 명 — 무료 1건으로 사례 만들기

> 목적은 돈이 아니다. **크몽이 승인되는 날 포트폴리오에 올릴 진짜 사례**를
> 지금 만들어 두는 것이다.
>
> 승인된 서비스는 리뷰 0건, 거래 0건으로 시작한다. 그 상태로는 검색에
> 뜨지도 않고 떠도 아무도 안 누른다. 옆에서 49,000원에 89건 팔리는 서비스는
> 리뷰가 쌓여 있어서 팔리는 것이다.
>
> **크몽 리뷰는 크몽 거래로만 쌓인다.** 바깥에서 한 건을 리뷰로 둔갑시키면
> 조작이다. 하지만 **포트폴리오에 실제 사례로 올리는 것은 정당하다.**
> 우리가 노리는 건 그것이다.

## 2일 동안의 순서

```
오늘      카페 가입 + 가입인사  → 등업은 시간이 걸린다. 지금 시작해야 한다
오늘~내일 정산·마진 질문 글에 댓글로 실제 도움을 준다
          그 중 한 명에게만 무료 제안을 건넨다
월요일    크몽 알림 확인 (#825703)
```

**홍보글을 따로 올리지 않는다.** 셀러 카페는 홍보를 막는다. 신규 회원이
올린 홍보글은 삭제되고 강퇴까지 간다. 유입 경로 하나를 통째로 잃는다.

대신 **질문에 답을 한다.** 답이 쓸모 있으면 상대가 먼저 묻는다.
그게 안 걸리고 가장 빠른 길이다.

## 무엇을 검색해서 댓글을 달까

`cafe.md` 에 적어 둔 검색어를 쓴다. 그 중에서도 **이 세 가지**가 걸린 글이
우리 사람이다.

```
정산서 봐도 얼마 남는지 모르겠다
이 상품 파는 게 남는 건지 모르겠다
수수료가 왜 이렇게 나왔는지 모르겠다
```

## 댓글 — 먼저 도움만 준다

제안은 여기 넣지 않는다. 이 댓글의 목적은 **쓸모 있는 사람으로 보이는 것**뿐이다.

```
정산서가 입금액까지만 알려주고 상품별로는 안 알려줘서 생기는 일입니다.

마켓 정산 파일에는 원가가 아예 없어서, 원가표를 따로 붙이지 않으면
상품별 순이익이 안 나옵니다. 그래서 총액만 보면 괜찮아 보이는데
쪼개보면 적자 상품이 섞여 있는 경우가 많습니다.

계산하실 때 두 가지만 조심하시면 됩니다.

수수료 부호가 마켓마다 다릅니다. 어떤 파일은 음수로 들어 있어서
그냥 더하면 수수료가 이익으로 더해집니다.

배송비는 주문 단위인데 상품 행마다 반복돼 들어 있는 경우가 있습니다.
행마다 더하면 배송비가 주문 건수만큼 부풀려집니다.
```

이 두 가지는 실제로 우리가 겪고 잡은 오류다. 그래서 설득력이 있다.

## 제안 — 대화가 이어졌을 때만

상대가 답글을 달거나 더 물으면, 그때 한 번만 건넨다.

```
혹시 괜찮으시면 제가 한 번 계산해 드릴까요.

정산 엑셀과 상품별 원가만 주시면 상품별 순이익표를 만들어 드립니다.
적자 상품이 있으면 얼마에 팔아야 본전인지까지 같이 내 드립니다.

돈은 안 받습니다. 대신 부탁이 하나 있습니다.
결과물에서 상품명과 금액을 가린 화면 한 장을 제 작업 사례로
쓰게 해 주시면 좋겠습니다. 싫으시면 그냥 안 쓰겠습니다.

파일은 이메일로 주시면 됩니다. sangyooncandoit@gmail.com

보내시기 전에 구매자 이름, 연락처, 주소가 든 열은 통째로 지워 주세요.
계산에 쓰지 않는 정보이고 제가 안 받는 편이 서로 안전합니다.
주문번호, 상품명, 금액, 수수료만 있으면 됩니다.
```

**사례 사용 동의를 먼저 받는다.** 받고 나서 묻는 게 아니라 주기 전에 묻는다.
싫다고 하면 그냥 해 주고 사례는 안 쓴다. 그래도 손해가 아니다 —
다음 사람에게 "해 본 적 있다"고 말할 수 있게 된다.

## 지키는 선

| 하지 않는다 | 왜 |
|---|---|
| 나이를 먼저 말하지 않는다 | 물으면 사실대로 답한다. 먼저 꺼내면 일이 아니라 사연이 된다 |
| 전화번호·카톡 아이디를 주지 않는다 | 이메일 하나면 충분하다. 처음 보는 사람이다 |
| 만나자는 말에 응하지 않는다 | 만날 이유가 없는 일이다 |
| 구매자 정보가 든 파일은 받지 않는다 | 들어 있으면 지우고 다시 보내 달라고 한다 |
| 돈 얘기를 먼저 꺼내지 않는다 | 무료 1건이다. 크몽이 열리면 그때 링크를 준다 |
| 못 하는 것을 된다고 하지 않는다 | 아래 '안 되는 것' 참고 |

## 받은 뒤 — 폰으로 하는 절차

PC 없이 폰만으로 끝까지 된다. 확인했다.

```
1. 메일에 온 엑셀 두 개를 폰에 저장한다
   정산 내역 / 상품별 원가

2. 파일에 구매자 이름·연락처·주소 열이 있는지 먼저 본다
   있으면 계산하지 말고 지워서 다시 보내 달라고 회신한다

3. 정산엑스레이.html 을 폰 브라우저로 연다
   tools/settlement/deliverable/정산엑스레이.html

4. 파일 선택 → 정산 엑셀을 넣는다
   컬럼은 자동으로 잡힌다. '자동 인식됨' 이 안 뜬 칸만 직접 고른다

5. 원가표를 넣는다

6. 결과 화면을 캡처한다
   - 손익 결과 (순이익·마진율·적자 상품 수)
   - 상품별 순이익 막대
   - 얼마면 본전인가

7. '표 복사' 를 눌러 엑셀로 붙여 넣을 표도 같이 보낸다
```

**이 도구는 파일을 어디에도 올리지 않는다.** 화면에 '업로드 없음 ·
기기 안에서 계산' 이라고 떠 있다. 상대가 물으면 그대로 말하면 된다.

## 회신 메일

```
제목: 정산 분석 결과 보내 드립니다

보내주신 파일로 계산한 결과입니다.

  순이익      OOO,OOO원  (마진율 OO.O%)
  매출        OOO,OOO원
  수수료      OOO,OOO원  (매출의 O.O%)
  원가        OOO,OOO원  (매출의 OO.O%)
  적자 상품   O개        (손실 OO,OOO원)

적자 상품이 있어 본전 판매가도 같이 계산했습니다.
지금 조건에서 순이익이 0이 되는 지점입니다. 수수료가 판매가에 비례해
같이 오르는 것까지 넣었습니다.

  OOOO   현재 OO,OOO원 → OO,OOO원이면 본전

화면 캡처와 엑셀에 붙여 넣으실 표를 함께 보냅니다.

숫자가 이상해 보이는 곳이 있으면 말씀해 주세요.
어느 행에서 나온 값인지 짚어 드리겠습니다.

감사합니다.
```

**마지막 줄이 중요하다.** 숫자를 믿으라고 하지 않고 확인해 보라고 한다.
처음 보는 사람이 만든 숫자다. 검증 가능하다는 말이 신뢰를 만든다.

## 안 되는 것 — 미리 말한다

- 마켓이 파일 형식을 바꾸면 컬럼을 못 잡을 수 있다. 그때는 직접 고르면 된다
- 광고비는 상품별로 나눠진 자료가 없으면 전체로만 반영된다
- 반품·교환이 복잡하게 얽힌 달은 숫자가 흔들릴 수 있다. 그런 달은 말해 준다

## 한 명이면 된다

열 명을 받으려 하지 않는다. 폰으로 하는 일이고 하루 두세 시간이다.
**한 명을 제대로 해서 사례 하나를 만드는 것**이 목표다.

사례 하나가 있으면 크몽 포트폴리오가 비어 있지 않게 된다.
그게 승인된 날 첫 거래를 가르는 자리다.
