## 왜 이걸 고르는가

**채점이 기계다.** 적격평가 100점이 전부 객관 지표다.

| 평가항목 | 배점 |
|---|---|

| 정답 추출 정확도 | 35 |
| 검출 시간 | 20 (상한 30분, 초과 시 0점) |

심사위원 취향도, 경력도, 소속도 안 본다. result.json 하나로 매긴다.
본심사도 절반(50점)이 적격평가 점수 환산이다.

**필수 탐지 4종이 전부 규칙으로 풀린다.** AI가 필요 없다.

LLM을 태우면 느려서 **검출 시간 20점에서 깎인다.** 규칙 엔진은 빠르다.
본심사 '도입 가능성'에도 API 비용 항목이 있어서, 외부 API를 안 쓰는
쪽이 오히려 유리하다. 외부 서버 장애로 평가를 망칠 위험도 없다.

# 10/2 — 1단계와 2단계 완료

## 윈도우 빌드 경로 — 확인됨

GitHub Actions 의 windows 러너에서 PyInstaller 단일 exe 가 빌드되고,
같은 러너에서 실행까지 됐다. Windows Server 2025(10.0.26100), Windows 11 과
같은 커널이다. 용량도 메일로 보낼 수 있는 선 안에 들어온다.

**그 과정에서 치명적인 버그를 하나 잡았다.**

    UnicodeEncodeError: 'charmap' codec can't encode characters

윈도우 콘솔 기본 코드페이지가 cp1252 라 한글을 찍는 순간 죽는다.
워크플로에서 chcp 65001 을 먼저 해도 파이썬 stdout 인코딩은 그대로다.
리눅스에서는 재현되지 않는다.

탐지 엔진을 먼저 만들고 나중에 발견했으면 심사 PC 에서 켜자마자 꺼져
그 자리에서 0점이었다. 순서를 지킨 값을 했다.

## 브라우저를 넣지 않기로 한 이유

접수가 이메일이다. Playwright 로 크로미움을 통째로 넣으면 exe 가
200MB 를 넘어 메일로 보낼 수가 없다. 느려서 검출 시간 20점에서도 깎인다.

대신 숨김과 관계있는 CSS 속성만 직접 계산한다. 전부 구현할 필요가 없다.
숨기는 데 쓰이는 속성은 열 개 남짓이다. 명시도와 !important, 상속,
@media 안쪽까지 처리한다.

## 만든 것

| 파일 | 하는 일 |
|---|---|
| `detect.py` | 탐지 규칙 4종 |
| `cascade.py` | 필요한 속성만 계산하는 작은 CSS 캐스케이드 |
| `selector.py` | 위치를 CSS 선택자로. 유일성까지 검증 |
| `lexicon.py` | 불법광고 신호어. 오탐을 막는 문지기 |
| `scan.py` | 수집과 판정 |
| `run.py` | result.json 생성 |
| `make_fixture.py` | 정답을 아는 테스트 사이트 |
| `serve_fixture.py` | 그 사이트를 띄우는 서버 |

## 정답을 아는 테스트 사이트부터 만들었다

평가 사이트는 공개되지 않는다. 그래서 공고문 붙임1 의 기법 설명과 붙임4 의
작성 예시를 근거로 같은 모양을 직접 만들고 정답표를 함께 적었다.
정산 도구 때 쓴 방법과 같다. 도구보다 자를 먼저 만든다.

함정도 같이 심었다. 스크린리더용 `sr-only` 와 접힌 메뉴다. 멀쩡한 사이트에도
숨긴 요소는 많고, 그걸 다 신고하면 정확도 35점이 깎인다.

**결과 — 정답 7건 전부 검출, 오탐 0건.**

## 고친 것 두 가지

하나. 수집기가 content-type 만 보고 페이지를 버렸다. 게시판 주소에 쿼리가
붙으면 서버가 octet-stream 을 주는 경우가 있는데, 그러면 페이지를 통째로
놓친다. 본문 앞머리를 보고 HTML 이면 읽도록 고쳤다.

둘. iframe 안에서 찾은 것의 url 을 iframe 문서 주소로 적고 있었다.
공고문 붙임4 예시는 바깥 페이지 주소를 적고 location 에 iframe[src] 를
붙인다. 채점이 (url + location + technique) 조합이라 이게 틀리면 그 건은
통째로 0점이다. 바깥 페이지 주소를 들고 다니도록 고쳤다.

안 쓴다는 것도 적어야 한다. 심사 환경에서 키를 꽂아 보려다 막히면 그게 감점이다.

윈도우 PC 없이 빌드하는 법, 고칠 때 손대는 자리.

## 윈도우에서 실제로 돌려 본 결과

워크플로를 새로 짰다. 빌드만 하고 끝내지 않는다.
시험용 사이트를 만들어 띄우고, 한글 출력까지 확인하며 exe 를 돌리고,
스키마 검사와 정답표 대조를 둘 다 통과해야 성공으로 친다.

```
exe 크기    : 15.1 MB          (상한 60MB — 메일로 보낼 수 있다)
윈도우 버전 : Microsoft Windows NT 10.0.26100.0
스키마      : 통과. 붙임4 요건을 모두 만족한다
정답 7건 / 신고 7건   맞게 찾음 7건 · 놓침 0건 · 오탐 0건
검출률 100.0%   정확도 100.0%
```

## 그 과정에서 잡은 것 세 가지

**하나. 매뉴얼에 적어 둔 그 오류로 빌드가 죽었다.**

    UnicodeEncodeError: 'charmap' codec can't encode characters

`app.py` 에만 보호를 넣어 두고 시험용 사이트를 만드는 쪽, 띄우는 쪽, 대조하는 쪽은
그대로였다. 워크플로 다섯 번째 줄에서 바로 터졌다. `winout.py` 하나로 모으고
한글을 찍는 스크립트가 전부 맨 앞에서 부르게 했다.

**둘. 자가 틀려 있었다.** `evaluate.py` 가 iframe 건을 오답으로 세고 있었다.
공고문이 iframe src 를 절대 주소로 적으라고 해서 도구를 그렇게 고쳤는데,
대조하는 쪽은 문서에 적힌 상대 경로와 문자열로 맞추고 있었다.
**도구가 아니라 자가 틀린 것**이다. 주소를 풀어서 비교하도록 고치니 7/7 이 된다.
자를 안 고쳤으면 "6/7 이구나" 하고 멀쩡한 코드를 뜯었을 것이다.

**셋. 경합 하나.** 작은 사이트는 탐지 스레드가 뜨기도 전에 화면이 상태를 물어 와서,
아직 시작도 안 한 것을 '끝났는데 결과가 없다'로 읽고 오류를 띄웠다.
스레드를 띄우기 전에 '돌고 있다'를 먼저 세운다.

그리고 `--url` 만 주고 창 모드로 켜면 화면만 열리고 아무 일도 안 일어났다.
심사자가 그렇게 켤 수 있다. 주소를 들려 보내 바로 시작하게 했다.

## 새로 둔 것 — verify_result.py

붙임4 요건만 따로 본다. 스키마를 어기면 그 항목은 채점에서 빠지고 파일이 깨지면
0점이라, 정답을 몇 개 찾았는지보다 먼저 통과해야 하는 관문이다.
최상위 구조, 필수 필드, technique 코드, id 중복, (url+location+technique) 중복,
iframe 표기, 소요 시간 상한을 본다. 일부러 망가뜨린 파일로 7가지를 다 잡는 것을 확인했다.

# 10/2 — 실제 사이트에 돌려 본 것이 제일 값을 했다

보내기 전에 실제 공공 누리집에서 속도를 재 보기로 했다. 속도만 보려던 것이었는데
**오탐 9건이 나왔고 전부 틀린 것이었다.** 시험용 사이트만 믿었으면 그대로 냈다.

## 처음 돌린 결과

```
mois.go.kr  65쪽 / 273초 / 쪽당 4.2초 / 검출 8건 — 전부 오탐
korea.kr    접힌 메뉴에서 1건 — 오탐
```

400쪽이면 28분. 상한 30분 바로 앞이다. 그리고 **CPU 시간이 벽시계의 89%**였다.
상대 서버가 아니라 우리 코드가 병목이라는 뜻이다.

## 고친 것 넷

**하나 — 속도.** 프로파일을 뜨니 CSS 선택자 2,618개를 페이지마다 문서 전체에
돌리고 있었다. 그런데 투명·화면밖은 어차피 '광고처럼 보인다'를 통과해야 신고한다.
**싼 검사를 먼저 하고 비싼 스타일 계산을 그 문을 통과한 요소에만** 하도록 순서를
바꿨다. 두 조건을 모두 만족해야 하므로 결과는 한 건도 바뀌지 않는다.

```
한 쪽 분석   4.35초 → 0.05초   (87배)
121쪽 전체   508초(환산) → 52초
CPU 점유     89% → 27%          네트워크가 병목인 정상 상태
```

**둘 — ⓒ 하나로 기사 전체가 잡혔다.** 뉴스 자막 끝의 저작권 기호다.
글 안에 수상한 글자가 하나라도 있으면 신고하는 구조였다. 낱말 단위로 바꾸고
기호·문장부호는 세지 않도록 했다. **`ⓒ ① ② ③ （） ％ Ω μ` 는 한국 공문서에
그냥 쓰는 글자다.** ①②③ 를 신고하는 도구를 공공기관에 돌릴 수는 없다.

**셋 — 장애인용 표 설명문이 '주유소·충전소' 때문에 잡혔다.** 사전에
'충전·대출·출장·성인·놀이터·환전'이 명백한 신호로 들어가 있었다.
공공 누리집에 널린 낱말이다. 등급을 둘로 나눠 일상어와 겹치는 말은
혼자서 문을 열지 못하게 했다.

**넷 — '오피니언'이 '오피'로 걸렸다.** 한국어는 낱말 사이에 띄어쓰기가 없어서
부분 문자열로 찾으면 더 긴 낱말에 묻힌 것까지 걸린다. 오피스텔·포커스·안마의자·
성인교육·사다리차·명품도시가 전부 같은 함정이다. 낱말마다 '뒤에 이게 붙으면
다른 뜻' 목록을 뒀다. @ 도 핸들만 보고 담당자 이메일 주소는 세지 않는다.

## 고친 뒤

8 그대로 둔다. 올리는 게 빠를 것 같지만 아니었다.
