## 왜 이걸 고르는가

**채점이 기계다.** 적격평가 100점이 전부 객관 지표다.

| 평가항목 | 배점 |
|---|---|
| 정답 검출 개수 | 45 |
| 정답 추출 정확도 | 35 |
| 검출 시간 | 20 (상한 30분, 초과 시 0점) |

심사위원 취향도, 경력도, 소속도 안 본다. result.json 하나로 매긴다.
본심사도 절반(50점)이 적격평가 점수 환산이다.

**필수 탐지 4종이 전부 규칙으로 풀린다.** AI가 필요 없다.

| 코드 | 무엇인가 | 어떻게 잡나 |
|---|---|---|
| HOMOGLYPH | 키릴·전각 등 닮은꼴 글자 섞기 | 유니코드 confusables 정규화 |
| JAMO | 음절을 자모로 쪼개기 | 자모 재결합 |
| TRANSPARENT | 배경색 동일, opacity:0, transparent | CSS 계산값 |
| OFFSCREEN | font-size 0~1px, left:-9999px, display:none | CSS 계산값 |

LLM을 태우면 느려서 **검출 시간 20점에서 깎인다.** 규칙 엔진은 빠르다.
본심사 '도입 가능성'에도 API 비용 항목이 있어서, 외부 API를 안 쓰는
쪽이 오히려 유리하다. 외부 서버 장애로 평가를 망칠 위험도 없다.

## 가장 큰 위험 — Windows 11

> 개발 산출물: **Windows 11에서 실행 가능한 구동 파일**

나는 리눅스에서 만든다. 사장님은 PC가 없다. **둘 다 윈도우에서
돌려볼 수가 없다.** 안 돌아가면 그 자리에서 0점이다.

해결 경로: GitHub Actions 의 windows 러너에서 빌드하고 거기서
바로 실행까지 시켜 본다. 실제 윈도우에서 빌드·구동된 결과물을
내려받는 것이라 "될 것이다"가 아니라 "됐다"가 된다.
**이 경로가 실제로 되는지부터 확인하고 시작한다.**

브라우저를 통째로 exe에 넣으면 무거워지므로, CSS 캐스케이드를
직접 계산하는 방식을 먼저 본다. 정적 HTML이면 이게 빠르고 가볍다.
